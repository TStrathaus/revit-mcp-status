2. Rules for taking a skill or a feature from GitHub

1. Licence first: MIT, BSD, Apache: code may be taken with the notice. LGPL: use as a library, do not copy code into ours. GPL / AGPL: run as a separate program or library only (pyRevit, PyMuPDF); no code copied into scan2revit. No licence: read only, take nothing. 2. Security check before use: every skill or script is read in full before it is installed or run: does a Markdown file or a hook make Claude execute code, download, install packages or call external services (as done for the geopogo skill folder). Skills go into .claude/skills/ only after that check. 3. Pinned: a dependency at a fixed version, a copied file at a commit hash, recorded with its licence in scan2revit/third_party/README.md (to create when the first file is copied). 4. Adapted, not trusted: a taken method gets our tests and the measured result in scoring.md before it replaces our own; no data from GitHub examples in our tests unless its licence allows it. 5. No customer data out: issues, questions or forks never contain project data, names or paths.

3. Contributing to the GitHub projects: what it would take (not decided)

Candidates (things we fixed or built that would help others):

  • pyRevit agent runtime: results too large for the response came back without result and without a path (we read them through get_run); IronPython json failing on umlauts; a relative workspace refused with an unclear message; Revit chosen by process id when several sessions run.
  • plan-extract: an importer of its JSON into native Revit through pyRevit (our fpx.py).
  • ifcopenshell: none so far.

Benefit

  • Fixes live upstream: fewer local workarounds (the get_run reading, the ASCII rules) to maintain.
  • Maintainers review the code; others report and fix bugs in it.
  • Visibility for the work; feedback from people who use Revit automation daily.
  • Influence on the direction of the tools we depend on (pyRevit's agent runtime is new and still changing).

Downside

  • Time for review cycles, which do not fit project deadlines.
  • Disclosure: methods become public (fine for generic fixes, a question for the scan-to-BIM methods).
  • Rights questions with the employer must be settled first.
  • Commitment: issues and questions about the contributed code come back.
  • A rejected or long-pending PR still has to be kept locally.

A lighter form (also not decided): bug reports as issues with a synthetic reproduction, no code. Low cost, most of the benefit for the pyRevit runtime findings.
